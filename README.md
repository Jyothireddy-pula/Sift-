# Sift — Document Summary Assistant

Upload a PDF or a scanned image and Sift extracts the text, then generates a structured
summary, key points, and concrete suggestions to improve the document — all wrapped in
an animated, glassy 3D interface.

**Live demo:** _add your deployed Vercel URL here after deploying_

---

## Features

- [x] **Document upload** — drag-and-drop or click-to-browse, PDF/PNG/JPG/WEBP, 10 MB limit, inline validation errors.
- [x] **Text extraction** — PDF text preserved page-by-page with line/paragraph structure ([lib/extractPdf.js](lib/extractPdf.js)); OCR for images via Tesseract.js ([lib/runOcr.js](lib/runOcr.js)).
- [x] **Scanned-PDF fallback** — if a PDF page has near-zero extractable text, that page is rendered to a canvas and OCR'd automatically.
- [x] **AI summary** — short / medium / long length control, generated by Gemini via a serverless route ([pages/api/summarize.js](pages/api/summarize.js)).
- [x] **Key points** — 3-6 bullet highlights returned alongside the prose summary.
- [x] **Improvement suggestions** — a second serverless route ([pages/api/suggestions.js](pages/api/suggestions.js)) critiques clarity, structure, and readability.
- [x] **Ask This Document (Q&A)** — a third serverless route ([pages/api/ask.js](pages/api/ask.js)) lets you ask free-form follow-up questions grounded only in the extracted text, with multi-turn conversation context ([components/AskPanel.jsx](components/AskPanel.jsx)).
- [x] **Document intelligence stats** — word count, estimated reading time, and a Flesch Reading Ease readability score computed client-side with no API call ([lib/textStats.js](lib/textStats.js)).
- [x] **Local history** — the last 10 summaries persist in `localStorage` (never leaves the browser) and can be reopened, deleted, or cleared from a slide-out drawer ([lib/history.js](lib/history.js), [components/HistoryDrawer.jsx](components/HistoryDrawer.jsx)).
- [x] **Retry without re-uploading** — if extraction or summarization fails, a Retry button re-runs just the failed step against the same in-memory file instead of forcing a fresh upload.
- [x] **Keyboard shortcut** — ⌘/Ctrl+Enter generates the summary once text is extracted.
- [x] **Responsive, animated UI** — glassmorphism cards, a real 3D wireframe-cube scene with perspective floor grid that reacts to pointer movement, gradient text, loading states for every async step.
- [x] **Copy / download** — copy summary to clipboard or download everything as a `.txt` file.
- [x] **Deployed with HTTPS** on Vercel; API key lives only in server environment variables.

## Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | Next.js (Pages Router) | UI + serverless API routes in one deployable repo. |
| PDF parsing | `pdfjs-dist` | Runs entirely client-side — no server cost, no upload of raw files. |
| OCR | `tesseract.js` | Client-side OCR for images and as a fallback for scanned PDF pages. |
| Summarization | Gemini 1.5 Flash (server-side) | Free tier, fast, called only from `/api/*` so the key never reaches the browser. |
| Styling | Tailwind CSS | Rapid, consistent, responsive styling with custom keyframe animations for the 3D background. |
| Hosting | Vercel | Native Next.js support, free tier, automatic HTTPS. |

## Architecture

```
Browser                                   Server (serverless)
┌────────────────────────┐                ┌───────────────────────┐
│ UploadZone              │                │ /api/summarize         │
│  → extractPdf.js (pdf.js)│──extracted────▶│  → Gemini API           │
│  → runOcr.js (Tesseract) │   text         │  (key stays server-side)│
│                          │                │ /api/suggestions        │
│ SummaryPanel renders     │◀──JSON─────────│  → Gemini API           │
│  summary/keyPoints/      │                └───────────────────────┘
│  suggestions             │
└────────────────────────┘
```

Text extraction happens entirely in the browser (no file upload needed), which keeps
the app fast and avoids storing user documents anywhere. Only the extracted plain text
is sent to the serverless summarization routes, and only from there to Gemini — so the
API key never touches client code.

## Local Setup

```bash
git clone <this-repo-url>
cd sift
npm install
cp .env.example .env.local   # then open .env.local and paste your real GEMINI_API_KEY
npm run dev
```

Then open http://localhost:3000 and test the full flow:
1. Upload a real text-based PDF → confirm extracted text preview looks correct.
2. Upload a real photo/scan of a document (or a screenshot of text) → confirm OCR extracts text.
3. Click "Generate Summary" for each of short/medium/long → confirm the lengths differ.
4. Confirm the Key Points and Improvement Suggestions sections both populate.
5. Try an unsupported file (e.g. `.txt`) and an oversized file → confirm friendly errors, not crashes.

Get a free Gemini API key at [Google AI Studio](https://aistudio.google.com/app/apikey).

## Deployment (Vercel)

1. Commit and push this repo to GitHub (`git add -A && git commit -m "..." && git push`).
2. Go to [vercel.com/new](https://vercel.com/new) and import the GitHub repo.
3. In the import screen (or Project Settings → Environment Variables afterward), add:
   - Key: `GEMINI_API_KEY`
   - Value: your real key
   - Scope: Production, Preview, and Development
4. Click **Deploy**. Vercel builds and gives you a `https://<project>.vercel.app` URL.
5. Open that URL in an incognito window and repeat the same 5-step test above — this is the version that gets graded.
6. Paste the working URL into the **Live demo** line at the top of this README, commit, and push again.
7. Take 2-3 screenshots (upload screen, summary results) and add them under a `## Screenshots` section here before submitting.

## Known Limitations

- Documents longer than ~20,000 characters are truncated before summarization (the UI flags this).
- OCR accuracy depends on scan quality/resolution — low-quality scans may extract text with typos.
- Gemini's free tier has rate limits; heavy concurrent use may return a transient error (retry).
- No persistence — documents and results are not stored; refreshing the page clears state.

## 200-Word Approach Write-up

Sift solves document summarization by splitting work between the browser and the
server based on cost and security, not convenience. Text extraction (pdf.js for PDFs,
Tesseract.js for images) runs entirely client-side, so raw documents never leave the
user's machine and the app incurs no server compute for parsing. A frequent edge case —
scanned PDFs with no embedded text layer — is handled by detecting near-empty pages and
falling back to rendering them as images for OCR, so the "PDF" and "image" paths
converge instead of failing silently.

Summarization and improvement suggestions, by contrast, run through a serverless API
route. This is the one part of the app that must be server-side: it holds the Gemini
API key, which would otherwise be exposed in the browser bundle. Two separate routes
(`/api/summarize`, `/api/suggestions`) keep each responsibility small and let the UI
show the summary immediately while suggestions load a beat later.

Given the time budget, I prioritized a fully working extraction → summary → suggestions
pipeline over extra features, then spent remaining time on UI polish — an animated,
pointer-reactive 3D background and glassmorphism panels — since a working feature set
with a strong first impression scores better than a longer feature list that's half-tested.
